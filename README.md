## 0. 폴더 구조

루트에는 **index.html**을 두고, 와이어프레임 등 index 외의 HTML 화면과 이 문서는 `pages/` 아래에 넣습니다. 강의가 끝날 때 최종 프로토타입은 `index.html`과 `pages/`의 마지막 와이어프레임이 같은 화면이어야 합니다.

```
index.html                 최종 프로토타입 (배포 주소에서 열리는 화면)
README.md                  이 문서 (변경 이력 · PRD · 주차별 작업 내용)
pages/                     와이어프레임 버전별 파일 (예: 와이어프레임_01_v0.5.html)
pages/index.html           루트 index.html과 같은 최종 화면 (tools/sync_pages.py로 생성, 경로는 ../)
css/style.css
js/                        config · firebase · app · data-sources · inventory-engine · inventory-ui · meal-planner · presentation · ui-icons
data/                      앱이 읽는 JSON 18개 + 식약처 원본 COOKRCP01_100.csv/.xlsx
demo/demo_users.json       시연용 가상 사용자 5명·요리 자랑 12건 (플래그 D, 실제 데이터와 분리)
asset/sprite.svg           썸네일·아이콘 그림 모음 (index.html 안에 인라인)
tools/                     데이터·화면 검사 스크립트, firestore.rules, 스프라이트 생성 도구, sync_pages.py(pages/index.html 생성)
```

`pages/index.html`은 직접 고치지 않고, 루트 `index.html`을 고친 뒤 `python3 tools/sync_pages.py`를 실행해 다시 만듭니다(`tools/inline_sprite.py`도 실행 끝에 자동으로 갱신). `pages/` 안의 HTML은 경로가 한 단계 아래라서 `../css/style.css`, `../js/app.js`처럼 `../`를 붙이고, 다른 스크립트보다 먼저 `<script>var APP_ROOT = '../';</script>`를 넣으면 `../data/`의 JSON을 읽습니다.

## 1. PRD v0.4

GitHub 기준 v0.4(2026-11-15, 빌드 v0.9.20)까지 구현된 내용을 정리한 요구사항 문서입니다. v0.5의 검색 필터 정리는 변경 이력과 2.2 참고.

### 1.1 문제 정의와 가치 제안

- **문제 정의 (4주차 C안)**: 자취 대학생은 집에 있는 재료로 만들 수 있는 요리를 한눈에 판단하기 어려워, 재료가 1~2개만 부족해도 요리를 포기한다.
- **가치 제안**: 가진 재료만 입력하면 지금 만들 수 있는 레시피를 바로 보여주고, 남은 재료·보관 기한까지 고려해 다음 끼니와 추가로 살 재료 하나를 알려준다.
- **v0.4에서 추가된 방향**: 한 번 검색하고 끝나는 서비스가 아니라, 냉장고 상태(수량·기한)를 계속 따라가는 서비스. (4주차 "범용 AI와 비교"에서 정한 차별점)

### 1.2 사용자

| 구분 | 정의 | 반영 방식 |

| 보조 사용자 | 요리 경험이 적어 쉽고 빠른 레시피를 찾는 1인 가구 | 별도 화면 없이 분류·조리 시간·난이도 조건으로 수용 |

### 1.4 MVP 범위

**4주차 MVP 정의**
사용자가 보유 재료를 여러 개 입력하면, 직접 구축한 레시피 데이터와 비교해 각 레시피를 바로 가능 / 1개만 더 있으면 / 대체하면 가능으로 분류하고, 부족 재료와 대체 재료를 목록에서 바로 보여준 뒤 상세 조리 정보까지 확인할 수 있는 웹 서비스.

**v0.4 MVP 정의**
사용자가 냉장고 재료를 수량·보관 기한과 함께 등록하면, 공공 레시피 데이터와 비교해 보유 재료를 활용하는 레시피를 보여주고, 상세에서 1인분 기준 필요량·보유량을 비교한 뒤 조리 완료 시 실제 사용량만큼 재고를 차감하는 웹 서비스. 조리한 요리는 게시물로 올려 주간 랭킹에 참여할 수 있다.

### 1.6 사이트맵

하단 탭 5개: **홈 · 레시피 · 요리 피드 · 랭킹 · 마이페이지**. 상단 바에는 로그인(원형 아이콘)만 둡니다. 냉장고는 마이페이지 › 냉장고, 임박 재료는 홈 배너로 알립니다. 깊이는 3단계를 넘지 않습니다.

```
냉장고 털이
├─ [탭] 홈
│   ├─ 레시피 찾기(재료 입력) ─→ 레시피 목록 ─→ 레시피 상세
│   ├─ 식사 계획 ─→ 조리 완료
│   ├─ 이것 하나만 사면 ─→ 레시피 상세
│   ├─ 인기 요리 자랑 ─→ 게시물 상세
│   └─ 이번 주 많이 만든 레시피 ─→ 레시피 상세
├─ [탭] 레시피 (목록 + 검색 통합)
│   └─ 레시피 상세 ─→ 조리 완료 ─→ 요리 자랑하기
├─ [탭] 요리 피드 (상단 검색)
│   └─ 게시물 상세 ─→ 레시피 상세
├─ [탭] 랭킹 (레시피 / 요리사 / 털이왕)
│   └─ 게시물 상세 · 레시피 상세
├─ [탭] 마이페이지
│   ├─ 즐겨찾기 · 내 레시피(─→ 레시피 등록) · 내 자랑 · 냉장고(월간 리포트 포함)
│   └─ 하단 메뉴: 데이터 명세 · 로그아웃
└─ [상단] 로그인 (─→ 회원가입 링크)
```

| # | 화면 (id) | 핵심 |
|---|---|---|
| 1 | 홈 `home` | 히어로(제목·설명·그림) + 레시피 찾기(재료 입력·칩·「전체 레시피 보기」) → 임박 배너 → 내 재료로 만들 수 있는 레시피 → 남은 재료 활용(식사 계획·하나만 사면) → 인기 요리 자랑 → 이번 주 많이 만든 레시피 |
| 2 | 레시피 찾기 `list` | 검색 + 내 재료 3단계(냉장고 재료 있을 때만) + 조건·정렬 패널(기본 접힘), 화살표로 더 보기. 건수 표시 없음 |
| 3 | 레시피 상세 `detail` | 돌아가기·홈 → 필요한 재료(있음/없음, 부족 알림, 1인분 비교) → 조리 순서·팁·영양 → 조리 완료 · 요리 자랑하기. 전체 사용자 기록 / 내 요리 기록 구분 |
| 4 | 레시피 등록 `new` | 사용자 레시피, 기준 인분 입력, 사진은 카메라·앨범(+)으로 |
| 5 | 요리 피드 `feed` | 상단 검색창, 최신순/인기순, 요리 게시물 목록, 좋아요·투표 |
| 6 | 랭킹 `rank` | 작은 필터(레시피·요리사·털이왕), 설명 두 줄 + 점수표 접기 |
| 7 | 게시물 상세 `post` | 돌아가기, 사진·후기·활용 재료(털이 인증), 좋아요·투표, 연결된 레시피 보기 |
| 8 | 요리 자랑하기 `write` | 조리 기록 연결, 사진 필수, 실제 난이도·시간(선택) |
| 9 | 마이페이지 `my` | 프로필 → 탭 4개(즐겨찾기 · 내 레시피 · 내 자랑 · 냉장고+월간 리포트) → 하단 메뉴(데이터 명세 · 로그아웃) |

### 1.7 User Flow

**흐름 A — 재료로 오늘 만들 레시피 고르기 (탐색)**
시작: 홈, 입력한 재료 없음 / 완료: 레시피 상세에서 냉장고와 비교까지 확인

| 단계 | 행동 | 결과 | 화면 |
|---|---|---|---|
| 1 | 홈에서 보유 재료 입력 후 Enter | 재료 칩이 쌓임 | 홈 |
| 2 | 「내 재료로 레시피 보기」 | 보유 재료가 들어간 레시피 목록 (건수는 표시 안 함) | 홈 → 레시피 |
| 3 | 보유 재료 "모두 포함"·분류 조건 선택 | 조건에 맞는 카드만 남음 | 레시피 |
| 4 | 카드 선택 | 재료·조리 순서·영양 정보 | 레시피 상세 |
| 5 | 「필요한 재료」에서 있음/없음과 부족 알림 확인, 필요하면 「필요량·보유량 비교」 | 부족한 재료·양 확인 | 레시피 상세 |
| 6 | (선택) 별로 즐겨찾기 | 마이페이지에 저장, 화면은 그대로 | 레시피 목록·상세 |

**흐름 B — 냉장고 등록 → 조리 → 게시물 → 랭킹 (개인화·참여)**
시작: 냉장고 비어 있음, 비로그인 / 완료: 게시물이 랭킹 점수에 반영

| 단계 | 행동 | 결과 | 화면 |
|---|---|---|---|
| 1 | 마이페이지 › 냉장고에 재료를 `150g`, `2개`처럼 수량·보관 기한과 등록 | 임박 재료가 있으면 홈에 알림 배너 | 마이페이지 |
| 2 | 레시피 상세에서 "조리 완료 · 사용량 반영" | 실제 사용량 확인·수정 | 레시피 상세 → 조리 완료 |
| 3 | 사용량 확인 후 완료 | 냉장고 재고 차감, 조리 기록 저장 | 조리 완료 |
| 4 | 「요리 자랑하기」 (비로그인이면 로그인) | 로그인 후 작성 화면 복귀 | 로그인 → 요리 자랑하기 |
| 5 | 사진·후기 입력, 조리 기록 연결 후 「자랑하기」 | 피드에 바로 표시, 재고는 다시 차감 안 함 | 요리 자랑하기 → 게시물 상세 → 요리 피드 |
| 6 | 랭킹 확인 | 털이 점수(게시·투표·재료 활용·임박 활용) 순위 | 랭킹 |

**흐름 C — 남은 재료로 여러 끼 계획하기**
시작: 냉장고에 재료 있음 / 완료: 계획한 끼니를 조리 완료로 반영

| 단계 | 행동 | 결과 | 화면 |
|---|---|---|---|
| 1 | 홈 → 「식사 계획」 | 하루 한 끼, 최대 7끼 추천 | 식사 계획 |
| 2 | 끼니별 예상 잔여량 확인 | 앞 끼니에 쓴 재료는 뒤 끼니에 다시 배정 안 함 | 식사 계획 |
| 3 | 끼니마다 "조리 완료 · 사용량 확인" | 실제 냉장고에 반영 | 조리 완료 |
| 4 | "완료한 끼니를 남기고 다시 계획" | 바뀐 냉장고 기준으로 남은 끼니 재추천 | 식사 계획 |

**주요 예외 처리**

| 상황 | 처리 |
|---|---|
| 재료 입력 없이 검색 / 결과 0건 | 빈 냉장고 그림 + 짧은 이유 + 다음 행동 버튼(조건 초기화 등). 홈의 빈 섹션은 그림 없이 한 줄 안내 |

| 재고 부족·단위 불일치로 조리 완료 | 차감을 막고 어떤 재료가 문제인지 표시 |
| 저장 공간 부족 / 저장 실패 | 이전 상태로 복원 |
| 삭제된 레시피의 게시물 | "레시피 삭제됨" 표시 |
| API 실패 | JSON 원본 유지, 실패 원인 기록 |

## 5. 실행과 검사

### 실행

이 폴더에서 `python -m http.server 8000` → `http://localhost:8000`. HTML을 더블클릭(file://)하면 브라우저가 JSON fetch를 막습니다. 배포는 GitHub Pages.

### 설정 (`js/config.js`)

- `API_KEY`: 식약처 식품안전나라 Open API 인증키. 정적 배포라 공개되는 구조(공공데이터 키, 한도 초과·유출 시 재발급)
- `FIREBASE_CONFIG`: Firebase 콘솔 → 프로젝트 설정 → 내 앱 → Config 값. 비우면 LocalStorage 로그인
- Firestore 규칙은 `tools/firestore.rules`를 콘솔 규칙 탭에 붙여넣기

데이터 파일·API·저장소는 1.8 데이터 정리 참고.

### 화면 파일

루트 `index.html`만 고치고 `python3 tools/sync_pages.py`로 `pages/index.html`을 다시 만듭니다.

### 디자인 기준

- 글자: 12(표식) · 14(본문·보조) · 16(카드 제목·버튼) · 18(섹션 제목) · 20(화면 제목) · 22(강조). 제목 아래 내용 = 제목 −2px
- 곡률: 카드 16px · 버튼·입력 12px · 작은 요소 8px · 칩 둥근 알약
- 버튼: 주요 = 진한 초록 채움, 보조 = 흰색 테두리, 삭제 = 붉은 테두리. 「더보기」·「펼치기」·「맨 위로」는 화살표 아이콘만
- 데이터 건수(76건 등)는 화면에 표시하지 않고 마이페이지 › 데이터 명세에서만 확인

### 수량 규칙

g↔kg, mL↔L만 환산하고 모↔g, 컵↔mL 같은 근거 없는 환산은 하지 않습니다. 원문에 기준 인분이 없으면 상세의 "레시피 수량 기준 확인·수정"에서 사용자가 직접 입력합니다. "조리 가능"은 등록된 수량·기한 기준 재료 비교 결과이고 조리 도구 같은 조건은 판단하지 않습니다.

### 검사

```
python tools/validate_data.py        # JSON 18개 필드·출처·ID·연결·건수
node tools/test_data_runtime.mjs     # JSON 로드·렌더링·모의 API·내보내기
node tools/test_meal_planner.mjs     # 식사 계획
node tools/test_inventory.mjs        # 수량 환산·차감·추가 구매
python tools/check_markup.py         # HTML 구조·중복 ID·참조
```

2026-11-17(빌드 v0.9.28) 기준 5개 모두 통과. (`demo/`는 `data/` 밖이라 데이터 검사 대상이 아님) 실제 브라우저에서의 Firebase 로그인과 공공 API 호출은 배포 주소에서 따로 확인해야 합니다.
