## 0. 폴더 구조

루트에는 **index.html**을 두고, 와이어프레임 등 index 외의 HTML 화면과 이 문서는 `pages/` 아래에 넣습니다. 강의가 끝날 때 최종 프로토타입은 `index.html`과 `pages/`의 마지막 와이어프레임이 같은 화면이어야 합니다.

```
index.html                 최종 프로토타입 (배포 주소에서 열리는 화면)
pages/README.md            이 문서 (변경 이력 · PRD · 주차별 작업 내용)
pages/                     와이어프레임 버전별 파일 (예: 와이어프레임_01_v0.5.html)
css/style.css
js/                        config · firebase · app · data-sources · inventory-engine · inventory-ui · meal-planner · presentation · ui-icons
data/                      앱이 읽는 JSON 18개 + 식약처 원본 COOKRCP01_100.csv/.xlsx
asset/sprite.svg           썸네일·아이콘 그림 모음 (index.html 안에 인라인)
tools/                     데이터·화면 검사 스크립트, firestore.rules, 스프라이트 생성 도구
```

`pages/` 안의 HTML은 경로가 한 단계 아래라서 `../css/style.css`, `../js/app.js`처럼 `../`를 붙이고, 다른 스크립트보다 먼저 `<script>var APP_ROOT = '../';</script>`를 넣으면 `../data/`의 JSON을 읽습니다.

## 1. PRD v0.4

GitHub 기준 v0.4(2026-11-15, 빌드 v0.9.20)까지 구현된 내용을 정리한 요구사항 문서입니다. v0.5의 검색 필터 정리는 변경 이력과 2.2 참고.

### 1.1 문제 정의와 가치 제안

- **문제 정의 (4주차 C안)**: 자취 대학생은 집에 있는 재료로 만들 수 있는 요리를 한눈에 판단하기 어려워, 재료가 1~2개만 부족해도 요리를 포기한다.
- **가치 제안**: 가진 재료만 입력하면 지금 만들 수 있는 레시피를 바로 보여주고, 남은 재료·보관 기한까지 고려해 다음 끼니와 추가로 살 재료 하나를 알려준다.
- **v0.4에서 추가된 방향**: 한 번 검색하고 끝나는 서비스가 아니라, 냉장고 상태(수량·기한)를 계속 따라가는 서비스. (4주차 "범용 AI와 비교"에서 정한 차별점)

### 1.4 MVP 범위

**4주차 MVP 정의**
사용자가 보유 재료를 여러 개 입력하면, 직접 구축한 레시피 데이터와 비교해 각 레시피를 바로 가능 / 1개만 더 있으면 / 대체하면 가능으로 분류하고, 부족 재료와 대체 재료를 목록에서 바로 보여준 뒤 상세 조리 정보까지 확인할 수 있는 웹 서비스.

**v0.4 MVP 정의**
사용자가 냉장고 재료를 수량·보관 기한과 함께 등록하면, 공공 레시피 데이터와 비교해 보유 재료를 활용하는 레시피를 보여주고, 상세에서 1인분 기준 필요량·보유량을 비교한 뒤 조리 완료 시 실제 사용량만큼 재고를 차감하는 웹 서비스. 조리한 요리는 게시물로 올려 주간 랭킹에 참여할 수 있다.

### 1.6 사이트맵

하단 탭 5개: **홈 · 레시피 · 요리 피드 · 랭킹 · 마이페이지**. 상단 바에 냉장고 바로가기(임박 재료 수 배지)와 로그인. 깊이는 3단계를 넘지 않습니다.

```
냉장고 털이
├─ [탭] 홈
│   ├─ 레시피 찾기(재료 입력) ─→ 레시피 목록 ─→ 레시피 상세
│   ├─ 식사 계획 ─→ 조리 완료
│   ├─ 이것 하나만 사면 ─→ 레시피 상세
│   └─ 인기 요리 게시물 ─→ 게시물 상세
├─ [탭] 레시피 (목록 + 검색 통합)
│   └─ 레시피 상세 ─→ 조리 완료 ─→ 게시물 작성
├─ [탭] 요리 피드
│   └─ 게시물 상세 ─→ 레시피 상세
├─ [탭] 랭킹 (요리 / 요리사 / 지난주)
│   └─ 게시물 상세 · 레시피 상세

### 1.7 User Flow

**흐름 A — 재료로 오늘 만들 레시피 고르기 (탐색)**
시작: 홈, 입력한 재료 없음 / 완료: 레시피 상세에서 냉장고와 비교까지 확인

| 단계 | 행동 | 결과 | 화면 |
|---|---|---|---|
| 1 | 홈에서 보유 재료 입력, 추천 칩으로 추가 | 재료 칩이 쌓임 | 홈 |
| 2 | "레시피 보기" | 보유 재료가 들어간 레시피 목록과 건수 | 홈 → 레시피 |
| 3 | 보유 재료 "모두 포함"·분류 조건 선택 | 조건에 맞는 카드만 남음 | 레시피 |
| 4 | 카드 선택 | 재료·조리 순서·영양 정보 | 레시피 상세 |
| 5 | "한 끼 분량 확인하기"에서 필요량·보유량 비교 | 부족한 재료·양 확인 | 레시피 상세 |
| 6 | (선택) 즐겨찾기 | 마이페이지에 저장 | 레시피 상세 |

**흐름 B — 냉장고 등록 → 조리 → 게시물 → 랭킹 (개인화·참여)**
시작: 냉장고 비어 있음, 비로그인 / 완료: 게시물이 랭킹 점수에 반영

| 단계 | 행동 | 결과 | 화면 |
|---|---|---|---|
| 1 | 내 냉장고에 재료를 `150g`, `2개`처럼 수량·보관 기한과 등록 | 임박 재료가 있으면 상단 배지 표시 | 마이페이지 |
| 2 | 레시피 상세에서 "조리 완료 · 사용량 반영" | 실제 사용량 확인·수정 | 레시피 상세 → 조리 완료 |
| 3 | 사용량 확인 후 완료 | 냉장고 재고 차감, 조리 기록 저장 | 조리 완료 |
| 4 | 게시물 등록 (비로그인이면 로그인) | 로그인 후 작성 화면 복귀 | 로그인 → 게시물 작성 |
| 5 | 사진·후기 입력, 조리 기록 연결 후 등록 | 피드에 게시, 재고는 다시 차감 안 함 | 게시물 작성 → 요리 피드 |
| 6 | 랭킹 확인 | 털이 점수(게시·투표·재료 활용·임박 활용)와 내 순위 | 랭킹 |

**흐름 C — 남은 재료로 여러 끼 계획하기**
시작: 냉장고에 재료 있음 / 완료: 계획한 끼니를 조리 완료로 반영

| 단계 | 행동 | 결과 | 화면 |
|---|---|---|---|
| 1 | 홈 → "식사 계획 만들기" | 하루 한 끼, 최대 7끼 추천 | 식사 계획 |
| 2 | 끼니별 예상 잔여량 확인 | 앞 끼니에 쓴 재료는 뒤 끼니에 다시 배정 안 함 | 식사 계획 |
| 3 | 끼니마다 "조리 완료 · 사용량 확인" | 실제 냉장고에 반영 | 조리 완료 |
| 4 | "완료한 끼니를 남기고 다시 계획" | 바뀐 냉장고 기준으로 남은 끼니 재추천 | 식사 계획 |

**주요 예외 처리**

| 상황 | 처리 |
|---|---|
| 재료 입력 없이 검색 / 결과 0건 | 빈 냉장고 그림 + 이유 + 다음 행동 버튼(조건 초기화, 재료 바꾸기) |
| JSON 불러오기 실패 | 빨간 "데이터를 불러오지 못했어요" + 경로·file:// 안내 |
| 재고 부족·단위 불일치로 조리 완료 | 차감을 막고 어떤 재료가 문제인지 표시 |
| 저장 공간 부족 / 저장 실패 | 이전 상태로 복원 |
| 삭제된 레시피의 게시물 | "레시피 삭제됨" 표시 |
| API 실패 | JSON 원본 유지, 실패 원인 기록 |

## 5. 실행과 검사

### 실행

이 폴더에서 `python -m http.server 8000` → `http://localhost:8000`. HTML을 더블클릭(file://)하면 브라우저가 JSON fetch를 막습니다. 배포는 GitHub Pages.

### 설정 (`js/config.js`)

- `API_KEY`: 식약처 식품안전나라 Open API 인증키. 정적 배포라 공개되는 구조(공공데이터 키, 한도 초과·유출 시 재발급)
- `FIREBASE_CONFIG`: Firebase 콘솔 → 프로젝트 설정 → 내 앱 → Config 값. 비우면 LocalStorage 로그인
- Firestore 규칙은 `tools/firestore.rules`를 콘솔 규칙 탭에 붙여넣기

데이터 파일·API·저장소는 1.8 데이터 정리 참고.

### 수량 규칙

g↔kg, mL↔L만 환산하고 모↔g, 컵↔mL 같은 근거 없는 환산은 하지 않습니다. 원문에 기준 인분이 없으면 상세의 "레시피 수량 기준 확인·수정"에서 사용자가 직접 입력합니다. "조리 가능"은 등록된 수량·기한 기준 재료 비교 결과이고 조리 도구 같은 조건은 판단하지 않습니다.

### 검사

python tools/validate_data.py        # JSON 18개 필드·출처·ID·연결·건수

```
