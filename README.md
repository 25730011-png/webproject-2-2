# 냉장고 털이

집에 있는 재료로 지금 만들 수 있는 요리를 찾아 주는 모바일 웹 (수업 팀 프로젝트). 7주차: `data/recipes.json`을 fetch로 연결하고, 데이터 점검(`checkData`)과 출처 표시(실제·더미·API 태그)를 적용했습니다.

## 실행

GitHub Pages 배포 주소에서 확인합니다. HTML을 더블클릭해 열면(file://) 브라우저가 fetch로 JSON 읽기를 막아 목록이 "불러오기 실패"로 표시됩니다. JSON은 `data/recipes.json` 또는 `data/json/recipes.json` 어느 쪽에 있어도 읽습니다. JSON을 고친 뒤에는 커밋·푸시 → Actions 탭에서 배포 완료 확인 → 강력 새로고침(Ctrl+Shift+R).

```
index.html
css/style.css
js/app.js            # 화면 전환 + loadData() · checkData() · loadApi() · renderList() · renderSearch() · openDetail()
data/COOKRCP01_100.csv   # 원본 데이터셋 (식약처 55열 + 플래그 열 8개) — 수정은 여기서
data/COOKRCP01_100.xlsx  # 같은 데이터의 엑셀 + 범례 + 출처·구분표 시트(강의 1.4.2)
data/recipes.json        # CSV에서 변환한 화면용 JSON (각 항목에 flag J/A + meta 출처 플래그)
data/ingredients.json · recipe_ingredients.json · substitutes.json
tools/csv_to_json.py     # CSV → recipes.json 변환 스크립트
```

## 데이터 출처

| 데이터 | 출처 | 건수 | 비고 |
|---|---|---|---|
| 레시피 (이름·조리방법·분류·재료·조리순서·영양정보·사진·팁) | **식품의약품안전처 식품안전나라 「조리식품의 레시피 DB」(COOKRCP01)** — https://www.foodsafetykorea.go.kr/api/openApiInfo.do · 공공데이터포털 https://www.data.go.kr (공공누리, 원본 페이지의 이용 조건 확인) | 76건 | 저장 JSON 사용 (API 미연동). 사진은 식약처 서버 링크 |
| 레시피 (이름·조리방법·분류·재료·조리순서) | **팀 직접 작성** (시연용, 검증 없음) | 24건 | id 90001~90024, `hashtag: "팀작성"`. 영양정보·사진·팁 없음 |
| 조리시간 `time` · 난이도 `level` | 팀이 규칙으로 임의 배정한 **더미** | 100건 | 조리방법 → 시간, 재료 수 → 난이도. 실제 값 아님 |
| 재료 사전 · 레시피-재료 · 대체 재료 | 팀 직접 입력 (와이어프레임용 더미) | 5·3·1건 | |
| 게시물 · 좋아요 · 별점 · 내 냉장고 | HTML에 직접 적은 예시 | – | JSON 데이터 아님 (이후 주차) |

- **식약처 API(COOKRCP01) 연동** (`js/app.js`의 `loadApi()`): 저장 JSON으로 먼저 화면을 그린 뒤 API에서 최신 값을 받아 식약처 레시피에 덮어씁니다. 받은 항목은 `meta.source: "api"`, 받은 필드는 `meta.api`에 기록되고 화면에 `API` 태그로 표시됩니다. 팀 작성 24건은 API 대상이 아니라 `json` 그대로입니다.
- API 연결에 실패하면(인증키 오류·네트워크·브라우저 차단 등) 저장 JSON 값이 그대로 보이고, 목록에 `API 연결 실패`, Console에 `[API 연결]` 경고가 표시됩니다.
- 레포가 Public이라 `app.js`의 인증키(`API_KEY`)는 누구나 볼 수 있습니다. 문제가 생기면 식품안전나라에서 재발급 후 이 값만 바꿉니다.
- 식약처 76건과 팀 작성 24건이 한 파일에 섞여 있으므로 "식약처 데이터 100건"으로 설명하지 않습니다. 화면에서는 카드마다 `식약처` / `팀 작성` 출처 칩, 값마다 `실제` / `더미` 태그로 구분합니다.
- 영양정보는 식약처 자료의 1인분 기준 참고값이며, 식약처 자료에 값이 없는 항목(중량 등)은 추정하지 않고 '정보 없음'으로 둡니다.
- 필드별 상세 구분·변환 규칙·한계는 `data/COOKRCP01_100.xlsx`의 출처·구분표 시트(1~6번) 참고.

## 출처 플래그 J / A (화면 표시)

| 표시 | 뜻 | 기준 |
|---|---|---|
| **J** (흰 바탕) | 저장 JSON 값 | 항목의 `flag: "J"` (`meta.source: "json"`) · 필드는 `meta.real` |
| **A** (검은 바탕) | 식약처 API에서 받은 값 | API 연결 성공 시 `flag: "A"` (`meta.source: "api"`) · 필드는 `meta.api` |
| **D** (점선) | 더미 값 | `meta.dummy` (조리시간·난이도, 팀 작성 레시피) |
| **null** (점선, 회색) | 빈 값 | 값이 `null` · `""` · `[]` |

- 카드(목록·검색·홈 추천)와 상세 제목 옆에 항목 플래그 **J/A**, 값마다 필드 태그 **J/A/D/null**을 붙입니다. 목록·검색·상세 위에 범례가 있습니다.
- 목록 상단 건수 옆에 `A 75 · J 24`처럼 플래그별 건수, API 실패 시 `API 연결 실패`가 표시됩니다.
- `ingredients.json` · `recipe_ingredients.json` · `substitutes.json`에도 `flag: "J"`를 넣었습니다.

## null(빈 값) 공통 표시 규칙

| 대상 | 값이 없을 때 화면 |
|---|---|
| 글자·숫자 필드 (재료, 팁, 영양, 중량 등) | 회색 **정보 없음** + `null` 태그 |
| 조리시간 / 난이도 | **시간 정보 없음** / **난이도 정보 없음** + `null` |
| 영양 정보 5개가 모두 없음 | 박스는 그대로, **영양 정보 · 정보 없음** 한 줄 |
| 조리 순서 `steps: []` | **조리 순서 정보가 없어요** |
| 썸네일 `image: null` | 같은 크기 회색 자리표시 + 🍽 **사진 없음** (카드·홈·상세 모두 같은 모양) |
| 사진 주소는 있는데 깨짐 | 같은 자리표시 + **사진을 불러오지 못했어요** (작은 썸네일은 사진 없음) |
| 로딩 중인 사진 | 회색 자리표시를 먼저 보여 주고 로드 (와이어프레임 '느린 네트워크' 예외) |
| 필수 값(id·name·method·category·ingredientsText·meta) 없음 | `checkData()`가 화면에서 제외, Console 경고 + 목록에 `점검 제외 N` |

## 레시피 검색 (JSON 데이터)

상단 🔍 → 검색 화면. 레시피 이름과 재료(`ingredientsText`)에서 찾습니다(공백 무시, 달걀=계란).
- 검색어 입력 전: 최근 검색어만 표시, ✕로 개별 삭제 (기기 로컬 저장, 저장소를 못 쓰면 "이번 실행에만 유지돼요")
- 입력 후: `레시피 N · 게시물 N` 탭, 카드마다 J/A 플래그와 내 냉장고 기준 배지, 보유 재료가 없으면 회색
- 결과 0건: **"이름 대신 재료로 찾아볼까요?"**와 홈 이동 버튼
- 상세에서 **← 검색으로** 누르면 검색어·탭 유지

## 와이어프레임 예외 흐름 적용

| 상황 | 화면 |
|---|---|
| 목록 결과 0건 | "이 재료를 추가하면 만들 수 있는 요리가 늘어나요" + 추천 재료 |
| 검색 결과 0건 / 입력 전 | 위 '레시피 검색' 참고 |
| 존재하지 않는 레시피 (예: 이번 주 요리의 계란말이·두부조림) | "레시피를 찾을 수 없어요" + 목록·홈 버튼 |
| 게시물의 원본 레시피 없음 (계란말이 게시물) | "따라 만들기" 비활성 → "원본 레시피 없음" |
| 레시피 데이터 로드 실패 | 오류 안내 + **다시 시도** 버튼, 입력한 재료 유지 |
| API 연결 실패 | 저장 JSON(J)으로 계속 표시, `API 연결 실패` 안내 |

## 데이터 수정 흐름

1. `data/COOKRCP01_100.csv`에서 레시피 값이나 플래그 열(`meta_source`·`meta_real`·`meta_dummy`·`meta_api`)을 고침 (엑셀로 열었다면 CSV UTF-8로 저장)
2. `python tools/csv_to_json.py` 실행 → `data/recipes.json` 재생성
3. 커밋·푸시 → 배포 주소에서 강력 새로고침 → F12 Console의 `[데이터 점검]` 확인
4. `COOKRCP01_100.xlsx`의 출처·구분표 시트도 같이 갱신

## 출처 플래그 (meta)

```json
// 식약처 원본 76건 (항목에 "flag": "J")
"meta": { "source": "json",
  "real":  ["name","method","category","weight","calories","carb","protein","fat","sodium",
            "hashtag","image","imageStep","ingredientsText","steps","tip"],
  "dummy": ["time","level"], "api": [] }

// 팀 작성 24건
"meta": { "source": "json", "real": [],
  "dummy": ["name","method","category","ingredientsText","steps","time","level"], "api": [],
  "note": "팀 작성 레시피 — 식약처 원본 아님, 영양정보·이미지·팁 없음" }
```

## 7주차 범위

- 한 것: JSON 연결(fetch), `checkData()` 점검(배열·건수·id 중복·자료형·허용값·필수 필드·출처 플래그), 목록·상세·홈 추천을 JSON으로 렌더링, 출처 칩·필드 태그, 이미지·영양정보·팁 등 추가 필드 표시
- 안 한 것(이후 주차): 난이도·조리시간 필터와 정렬, 재료 매칭 로직 고도화(현재는 재료 텍스트에 보유 재료 이름이 포함된 수만 셈), 즐겨찾기 저장
- 추가: 식약처 API 연동 (`loadApi()`, 실패 시 저장 JSON 유지), 출처 플래그 J/A 표시, null 공통 표시와 예외 테스트 데이터 5%, JSON 레시피 검색, 와이어프레임 예외 흐름

## 데이터 점검 결과 확인

배포 주소에서 F12 → Console의 `[데이터 점검] ./data/recipes.json` 그룹을 펼치면 건수 100, `항목 출처: {json: 100} | 플래그: {J: 100}`, `작성 주체: {식약처: 76, 팀작성: 24}`, 예외 테스트 5건(5%) 목록, 경고 `필수 필드 누락: id 127 ingredientsText → 화면에서 제외`, 화면에 표시할 건수 99가 표시됩니다. 이어서 `[API 연결]` 그룹에 API 수신 건수와 갱신 건수(75건, flag J → A)가 표시됩니다.
