# 냉장고 털이

집에 있는 재료로 지금 만들 수 있는 요리를 찾아 주는 모바일 웹 (수업 팀 프로젝트). 레시피 **310건**(식약처 공개 76 + 팀 작성 24 + AI 가상 210 + 사용자 등록)을 JSON으로 연결하고, 모든 카드에 출처 플래그를 붙이며, 검색 조건·스와이프·게시물·**주간 요리 경진대회(랭킹)**·데이터 명세 페이지까지 갖춘 결과물입니다.

하단 메뉴 5개: **홈 · 레시피(목록+검색) · 피드 · 랭킹 · 마이**. 사용자가 들어와서 가장 먼저 하는 일이 레시피 보기라서, 히어로 어느 슬라이드에서든 보이는 「레시피 보러 가기 (N건)」 버튼과 홈 검색·조건이 바로 레시피 화면으로 이어집니다.

## 실행

GitHub Pages 배포 주소에서 확인합니다. **HTML을 더블클릭해 열면(file://) 브라우저가 fetch로 JSON 읽기를 막아** 레시피 탭의 요약 바가 "불러오기 실패", 홈의 레시피·요리 섹션이 "보여줄 수 없어요" 안내로 뜹니다 — 코드 문제가 아니라 브라우저 보안 규칙(강의 1.1.3)입니다. 그림(스프라이트)은 index.html에 들어 있어 file://에서도 보입니다. 로컬에서는 VS Code Live Server 또는 `python -m http.server 8000` → `http://localhost:8000`. JSON을 고친 뒤에는 커밋·푸시 → Actions 배포 완료 → 강력 새로고침(Ctrl+Shift+R).

```
index.html
css/style.css
js/app.js                # 화면 전환 + loadData/checkData/renderList/openDetail + fetchApi + 필터·스와이프·게시물·명세
js/config.js             # 식약처 Open API 인증키(API_KEY), Google Sheets 웹앱 URL(SHEET_WEBAPP_URL, 선택)
js/config.example.js     # config.js 양식
data/COOKRCP01_100.csv   # 원본 데이터셋 100건 (식약처 55열 + 플래그 열 10개) — J·A 수정은 여기서
data/COOKRCP01_100.xlsx  # 같은 데이터의 엑셀 + 범례 + 출처·구분표 시트 1~7 (강의 1.4.2)
data/recipes.json        # CSV에서 변환한 J 76 + A 24 (각 항목 flag·author·meta)
data/recipes_dummy.json  # AI(Claude) 생성 가상 레시피 210건 (flag D) — 300건 이상 검색 시연용
data/user_recipes.json   # 사용자 등록 레시피(U). 처음엔 []. 마이 › 내 레시피 › JSON 내보내기로 교체
data/posts.json          # 사용자 게시물(U). 처음엔 []. 마이 › 내 게시물 › JSON 내보내기로 교체
data/ingredients.json · recipe_ingredients.json · substitutes.json   # 재료 사전 (flag J) — 추천 칩·표기 통일에 사용
asset/sprite.svg         # 그림 모음 한 파일(39개 symbol): 썸네일 36장 + 빈 냉장고 + 사진없음 접시 + 히어로 그림. tools/inline_sprite.py가 index.html 안에 넣어 두므로 화면은 <use href="#t01">로 씀 (파일로 바로 열어도 그림은 보임)
tools/csv_to_json.py     # CSV → recipes.json
tools/make_dummy.py      # recipes_dummy.json 생성 (결정적)
tools/make_thumbs.py     # asset/sprite.svg 생성 → inline_sprite.py 자동 실행
tools/inline_sprite.py   # sprite.svg를 index.html <!-- sprite:start/end --> 사이에 삽입
tools/sheets_webapp.gs   # Google Sheets를 DB로 쓰는 Apps Script (선택)
```

## 데이터 형태와 플래그 — 모든 카드·상세에 한 글자 아이콘

| 플래그 | 모양 | 데이터 | `meta.source` | 값의 성격 |
|---|---|---|---|---|
| **J** | 실선 네모 | 식약처 「조리식품의 레시피 DB」 76건, 저장 JSON | `json` | 실제 공개 데이터. `time`·`level`만 더미 |
| **A** | 검정 네모 | 팀 작성 24건, 저장 JSON + 상세에서 식약처 Open API 호출 | `api` | 이름·재료·조리법은 팀 작성 더미, 영양정보·사진·팁은 API 응답(실패 시 `대체`) |
| **D** | 노란 점선 네모 | AI(Claude) 생성 가상 레시피 210건 | `dummy` | **전 필드 가상.** 실제 조리법·영양 아님. 카드에 "AI 가상" 칩, 상세에 경고문, 출처 필터 "가상 제외"로 뺄 수 있음 |
| **U** | 초록 점선 네모 | 사용자가 등록한 레시피·게시물·좋아요·즐겨찾기 | `user` | 사용자 입력값(검증 없음). 브라우저 localStorage + JSON 내보내기 |

값 옆 작은 태그 `실제`/`더미`/`API`/`대체`/`사용자`는 그 값이 어디서 왔는지(강의 1.4.5). `checkData()`가 `flag`와 `meta.source` 불일치, API 플래그 오류, id 중복, 자료형·허용값을 Console에 경고합니다. 정의·건수·필드 명세·API 규격은 화면 **마이 › 데이터 명세**(라이브 집계)와 `data/COOKRCP01_100.xlsx`에 있습니다.

## 화면 구성 (와이어프레임)

| # | 화면 | 핵심 |
|---|---|---|
| 1 | 홈 | **히어로**(글 + 그림) 안에 **「레시피 찾기」 카드**: 보유 재료 입력(기본 재료 없음) · 추천 칩 → 버튼 하나. 재료가 없으면 「레시피 전체 310건 보기 →」, 재료를 넣으면 「이 재료로 만들 수 있는 레시피 N건 보기 →」로 바뀜(별도 전체 보기 링크 없음) → 좋아요 많은 인기 요리(3장 스와이프) → 바로 만들 수 있는 레시피 → 이번 주 많이 만든 요리. |
| 2 | 레시피 (목록+검색 통합) | **검색 패널 한 상자** = ① 검색(검색창 + 보유 재료 3단계: 상관없음/하나라도 포함/모두 포함 + 재료 칩) ② 조건(분류·시간·난이도·방법·출처, 라벨 고정 폭으로 왼쪽 정렬, 접기/펼치기) ③ 정렬 + 맨 아래 "적용 중: … 초기화" 요약. 30건씩 더 보기 |
| 3 | 레시피 상세 | 사진 위 양옆 ‹ › 화살표 + "2 / 196" 위치, 제목 줄 오른쪽 ☆ 즐겨찾기 원형 버튼, 난이도 태그, 출처 칩·플래그, 작성자, "이 레시피로 만든 요리 n건", 재료·조리순서·영양·팁·API 정보, **좌우 스와이프로 이전/다음**, 「이 레시피로 요리했어요 · 공유」 |
| 4 | 요리 피드 | 요리 게시물 최신/인기순, 내 냉장고 필터, ♥ 좋아요(공감=투표), 난이도 표시, 삭제 · 요리 검색 탭 |
| 5 | 요리 상세 / 요리 올리기 | 사진·후기·사용 재료·난이도·♥ 좋아요·「이 요리의 레시피 보기」 / 레시피 선택·사진(필수)·후기 100자 (별점 없음), 로그인 필요 |
| 6 | **랭킹 (경진대회)** | 이번 주(월~일) 요리 게시물로 **요리 랭킹·요리사 랭킹·지난 주 결과** 3탭, 마감 카운트다운, 내 순위 카드. 👍 추천 = 투표 |
| 7 | 마이 | 즐겨찾기 레시피 · 내 레시피(등록·삭제) · 내가 만든 요리 · 내 냉장고 · 데이터 명세 · 로그아웃 (로그인은 상단바 버튼) |

| 9 | 레시피 등록 / 데이터 명세 | U 등록 폼 / 구성 집계·플래그·필드·API 규격·예외 규칙 (서브 페이지) |

## 경진대회(랭킹) 로직

- **기간**: 월요일 00:00 ~ 일요일 24:00. 월요일에 새로 시작, 지난 주는 「지난 주 결과」 탭에 1~3위와 최다 인증 레시피
- **참여**: 레시피 상세 → 「이 레시피로 요리했어요 · 공유」로 사진 게시물을 올리면 자동 참여 (로그인 필요). 다른 사람의 👍 추천이 표
- **점수** = 요리 게시물 1건 **10점** + 받은 **👍 추천** 1개 **3점**. ♥ 좋아요는 공감 표시라 점수에 안 들어감. 별점 없음. 동점이면 표 → 게시물 수 순
- **요리 랭킹**: 같은 레시피로 만든 요리 게시물의 점수 합. 카드를 누르면 레시피 상세
- **요리사 랭킹**: 작성자별 점수 합, 대표작(좋아요 최다 게시물). 내 행은 초록 배경
- 점수는 저장하지 않고 화면에서 게시물로 매번 계산(`renderRank()`). 게시물이 이 브라우저에만 저장되므로 지금은 "내 브라우저 안의 대회"이며, 서버를 붙이면 같은 규칙으로 전체 집계로 바뀜
- 0건이면 빈 냉장고 표준 화면 + "첫 게시물이면 1위!" 안내

## 검색 조건 설계 (UX)

사용자가 실제로 결정하는 축만 남겼습니다. **뭘 먹을지**(분류) · **얼마나 바쁜지**(시간) · **할 수 있는지**(난이도) · **어떻게**(조리방법) · **믿을 수 있는지**(출처, 가상 제외) · 정렬. 기본 정렬 "추천순"은 이름 일치 → 보유 재료 포함 수 → 실제 데이터 우선 → 가나다. 조건이 걸린 0건 화면에는 "검색 조건 초기화"가 첫 버튼으로 나옵니다. 모든 조건은 목록·검색 화면이 공유합니다.

## 예외 케이스 표준 가이드

모든 '없음'은 **빈 냉장고 그림 + 무엇이 없는지 + 왜/어떻게 + 다음 행동 버튼**(`emptyState()`)으로 통일. '불러오기 실패'만 빨간 테두리(강의 1.2).

| 상황 | 표시 |

## 데이터 수정 흐름

1. J·A: `data/COOKRCP01_100.csv` 수정(엑셀이면 CSV UTF-8 저장) → `python tools/csv_to_json.py`
2. D: `tools/make_dummy.py`의 BASE/VAR 수정 → `python tools/make_dummy.py` (같은 입력이면 같은 결과)
3. U: 화면에서 등록 → 이 브라우저 localStorage에 저장. 팀 저장소에 반영하려면 F12 Console에서 `JSON.stringify(store.get('recipes'))` / `store.get('posts')`를 복사해 `data/user_recipes.json`·`data/posts.json`에 붙여넣기 (화면의 내보내기 버튼은 교수님 피드백으로 제거)
4. 커밋·푸시 → 배포 주소 강력 새로고침 → F12 Console `[데이터 점검]`: `항목 출처: {json: 76, api: 24, dummy: 210, user: n}`, 경고 없음
5. `COOKRCP01_100.xlsx` 출처·구분표 시트 갱신

## Google Sheets를 DB로 쓰기 (선택)

서버 없이 기록만 남기는 용도. 구글 시트 → 확장 프로그램 › Apps Script → `tools/sheets_webapp.gs` 붙여넣기 → 웹 앱으로 배포(액세스: 모든 사용자) → URL을 `js/config.js`의 `SHEET_WEBAPP_URL`에 넣기. 로그인·레시피 등록·게시물 작성 때 시트 `login`/`recipe`/`post`에 한 줄씩 쌓입니다(no-cors라 응답은 읽지 않음). 비워 두면 localStorage만 씁니다.

## API 연동 확인 순서

1. F12 Console에서 `fetch('https://openapi.foodsafetykorea.go.kr/api/' + API_KEY + '/COOKRCP01/json/1/1/RCP_NM=김치찌개').then(r => r.json()).then(console.log)` — 키·CORS 확인

4. 키를 틀리게 한 뒤 다른 A 레시피 → `정보 없음 [대체]` + Console `[API 대체]`, 화면은 깨지지 않음
